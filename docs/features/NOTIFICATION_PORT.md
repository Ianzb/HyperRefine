# 通知功能

入口：**功能 → 系统界面 → 通知**（独立分区），或在功能页搜索通知功能。通知组侧滑裁切默认关闭，与其余七项一致，沿用 HyperRefine 的配置同步、导入导出、作用域申请及安全模式。

## 功能与作用域

| 开关 | 行为 | 所需作用域与应用方式 |
| --- | --- | --- |
| 通知组侧滑裁切 | 通知组内子通知侧滑时，临时扩展父级裁剪范围，避免被组边缘裁切 | 系统界面，重启系统界面 |
| 通知留在锁屏 | 解锁后再次锁屏时，仍显示尚未清除的通知 | 系统界面，重启系统界面 |
| 强制允许锁屏通知 | 解除应用和渠道的锁屏资格限制 | 系统界面，重启系统界面 |
| 强制允许悬浮通知 | 解除应用和渠道的悬浮资格限制 | 系统界面，重启系统界面 |
| 解除通知修改限制 | 允许关闭原本受保护的系统通知和渠道 | 系统界面、系统设置、系统框架，完整重启设备 |
| 通知重要程度 | 开放渠道重要程度设置，并处理最低重要度的状态栏图标 | 系统设置、系统界面，重启两者 |
| 停止折叠历史通知 | 解除历史通知折叠，保持通知在正常列表显示 | 系统界面，重启系统界面 |
| 取消每应用 10 条通知限制 | 解除每应用通知数量的显示过滤 | 系统界面，重启系统界面 |

LSPosed 的对应作用域为 **系统界面** `com.android.systemui`、**系统设置** `com.android.settings`、**系统框架** `system`。这些目标已在 scope.list 中声明，开关只申请各自所需范围。

锁屏保留不能重新创建用户已清除或应用已撤回的通知。悬浮资格解锁后，其他系统展示条件仍适用。每应用数量选项解除 SystemUI 显示过滤，不改变通知服务的其他入队配额。

重要程度在系统的 **应用通知 → 通知渠道** 页面调整，保存选择并锁定用户选择；后端拒绝保存或抛异常时恢复原重要程度及原用户锁定位。最低重要度（0/1）不显示状态栏图标，保留参考模块的另一映射分支，不自动提升所有通知的重要程度。

涉及多个进程的两个选项不显示单一「已生效」标记，避免部分进程安装成功被误认为整项生效；仍保留各进程的安装上报和模块日志。其余单进程选项沿用现有状态显示。

## 通知组侧滑裁切

通知组展开后，子通知横向滑动时如果只平移子 View，父级摘要行的 `clipBounds` 仍固定在 `[0, width]`，滑出组边缘的部分会被裁掉；普通通知是整行平移，行自身的裁剪范围会跟着移动，所以不受影响。

模块在系统界面进程内挂载该修复：子通知滑动期间临时把父级摘要行的裁剪范围向左右各扩一个通知宽度，同时保留原有的上下高度裁剪；松手、复位或子通知离开后恢复原值。该修复不改变通知组的折叠/展开逻辑，默认关闭，可在通知功能页开启。安装新包后需重启系统界面生效。

## 验收步骤

逐项验收可按上表开启单个功能、重启对应目标后检查：

1. 收到通知 → 解锁 → 再锁屏，检查未清除通知仍显示；清除后不应重新出现。
2. 关闭某应用/渠道的锁屏或悬浮资格，再发送一条新通知，检查对应资格解锁。
3. 修改原本不可关闭的系统通知/渠道，并在重启后检查保存情况。
4. 调整渠道重要程度，退出再进入确认保存；检查最低重要度图标。
5. 检查原本移入历史区域的通知保持在正常列表。
6. 同一应用发送超过 10 条不同 ID 的通知，检查显示数量。

验收时应关闭其他模块的同名功能，以便判断本模块效果。
