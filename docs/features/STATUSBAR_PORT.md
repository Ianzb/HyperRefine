# 状态栏功能说明

入口：**功能 → 系统界面 → 状态栏**。以下开关默认关闭，目标均为 `com.android.systemui`；修改后重新加载系统界面进程生效。

> 新的图标自定义框架（左侧/右侧分组、统一显示条件、布局与时间/网速/通知专属参数）见 [状态栏图标自定义](STATUSBAR_ICON_CUSTOMIZATION.md)。原有三个功能不再单独堆在主页底部，而是分别并入 Wi‑Fi / 移动网络组件详情；总开关首次启用需要重启系统界面，之后的显示/条件/布局与右侧排序均即时刷新。

| 选项 | 配置键 | 效果 |
|---|---|---|
| 隐藏 Wi-Fi 网络活动指示器 | `statusbar_wifi_hide_activity` | 隐藏 Wi-Fi 的收发活动图标，保留信号与连接显示 |
| 完全隐藏网络类型 | `statusbar_mobile_hide_type` | 隐藏移动网络类型图片、独立文字和特殊 5G 标识，保留原生信号布局 |
| 显示双排堆叠信号 | `statusbar_mobile_dual_rows` | 将两个蜂窝信号合并为上下各四格，上排 SIM 1、下排 SIM 2 |

## 实现与验证

Wi-Fi Hook 在原生绑定与活动更新之后将对应活动视图隐藏，避免后续收发更新再次显示。移动网络类型 Hook 在原生蜂窝模型创建后，将四个类型显示 Flow 替换为宿主自身的只读 false Flow；兼容宿主经过优化的一参数构造与普通二参数构造。

配置通过项目既有 `OptionSpec`、偏好与 Hook 状态机制接入；状态栏子页面继承 `BaseSubPageActivity`，登记到父页搜索，并使用 `NetworkIconsActivity`。没有新增权限、作用域或原生依赖。

接口静态核对基于当前设备 HyperOS `OS4.0.5.0.XPMCNXM`（Android 17）、SystemUI `17.03.260226.r`；其他 ROM 的私有接口兼容性尚未验证。用户先前已确认两个隐藏功能生效、关闭双排时保持原生布局，从状态栏页下拉通知中心/控制中心时背景显示正常。本轮恢复双排后，用户确认下拉通知中心、控制中心和返回桌面时双排无跳变，最终文案与三个功能均无异常。单元测试覆盖配置键、反射成员解析、只读 Flow 构造、图形比例、模型回退和绘制前事件处理；没有新增临时诊断日志。

## 双排堆叠信号

此前注释保留的双排实现和对应测试现已恢复。双排使用审阅通过的普通宽度、紧凑圆角图形；图形以 16×20 视口为基准整组垂直居中，上排与下排之间保留约 16% 视口高度的间距，不再贴着宿主底部。移除加粗样式和整个样式下拉框，旧 `statusbar_mobile_dual_style` 偏好不再读取。缩放与左右间距继续提供，仅依赖双排开关；左右间距为原生间距的增量。垂直偏移不再在双排区重复滑条，统一使用「移动网络」详情页布局的“上下偏移”，作用于整个移动网络图标。

图形在固定 16×20 的逻辑坐标中定义，整组在宿主 bounds 内等比缩放并垂直居中，不再依赖原生主题图片的固有尺寸。主题、明暗和信号变化更新同一 Drawable；原生收集器返回前立即刷新，并在绘制前清理尚未合并的更新。临时隐藏、圆点及透明度动画不当作 SIM 消失，不因这些展示状态恢复原生单排图形。用户缩放与偏移在 Drawable 内完成，不覆盖 ImageView 的缩放或父容器的平移动画。

仅对同一宿主中两张可见蜂窝 SIM 合并；单卡、无可识别强度、卫星或仅 VoWiFi 时恢复原生显示。灰格与亮格保留宿主着色和透明度。双排的模型订阅继续使用原生 JavaAdapter，不新增轮询。开关及四个布局偏好沿用旧键，保留已有配置；关闭双排并重新加载系统界面可恢复原生布局。

用户已在 `1.13.0-dualsim.1`（versionCode 30）确认下拉 Control center / notification shade、返回桌面时双排无跳变，并在 `1.13.0-dualsim.2-ui`（versionCode 31）确认最终文案和三个功能正常。两包全部 DEX 和原生库逐字节一致；后一包仅修改文案资源和测试版本号。单双卡/数据卡切换、卫星、仅 VoWiFi、锁屏及主题/明暗切换尚未收到本轮逐项真机记录，不能用已有反馈代替这些覆盖。已合并的两个隐藏 Hook 保持原样。

电脑端素材包已删除加粗 PNG/SVG 与包含加粗示例的旧预览，保留 50 张普通 PNG 和 2 张普通 SVG；这 52 个文件的内容与此前审阅版本一致。它们不是运行时依赖，未进入仓库或 APK。当前构建没有图标解包、图片落盘或系统资源替换。

## 参考与安全边界

功能思路参考 Pengeek（米客）`OS4-26.10.13-test`，来源与许可在应用内「关于 → 第三方许可证与致谢」统一登记。实现独立编写，未复用参考模块或小米专有代码/资源；逆向材料仅保留在本地忽略的 `reverse_report/`。项目继续以 AGPL-3.0 分发。

新增 Hook 仅修改 SystemUI 进程中的视图、显示 Flow 与内存 Drawable，不请求 Root、不执行 shell、不挂载或重新挂载分区、不操作块设备/AVB，也不向受保护系统分区写文件。安装 APK、项目既有偏好及系统/框架日志仍可能保存普通应用数据，因此此说明不承诺整个模块或临时 Root 环境的所有组件均无写入。
